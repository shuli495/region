# 全球行政区划

基于 **Next.js + React + MySQL** 的全球行政区划查询与管理平台。国内数据来自民政部，海外数据来自 GeoNames 和 OpenStreetMap。

## 功能

- 区划浏览与中国区划编辑，自动记录修改日志。
- 拉取代码后发现新数据包，在后台一键更新。
- 民政部数据同步、冲突处理、版本发布与回退。
- API Key 创建、有效期管理、启停、轮换和撤销。
- 按日期、Key、接口查看调用量、错误数及平均耗时。

## 快速启动

需要 Node.js 22+、npm 和 MySQL 8+。

```shell
npm ci
cp .env.example .env.local
```

填写 `.env.local` 中的数据库连接参数。首次使用空数据库时，先[建表并导入数据](#初始化数据)，已有数据无需重复导入。

```shell
npm run dev
```

| 入口 | 地址 | 访问方式 |
| --- | --- | --- |
| 控制面板 | [http://localhost:3099/](http://localhost:3099/) | 管理令牌登录 |
| API 文档 | [http://localhost:3099/docs](http://localhost:3099/docs) | 无需登录 |

未配置 `REGION_ADMIN_TOKEN` 时，启动会随机生成管理令牌并打印到控制台，重启后更换；配置后使用指定值，不限制长度或格式。页面刷新后需重新登录。

## 配置

Next.js 和 `npm run data:*` 命令均会读取 `.env.local`。完整示例见 [.env.example](.env.example)。

| 配置 | 说明 |
| --- | --- |
| `MINE_MYSQL_HOST` / `MINE_MYSQL_PORT` | 数据库地址与端口，默认端口 3306 |
| `MINE_MYSQL_DATABASE` | 数据库名称，默认 region |
| `MINE_MYSQL_USER` / `MINE_MYSQL_PASSWORD` | 数据库账号与密码 |
| `REGION_ADMIN_TOKEN` | 可选的固定管理令牌，留空自动生成 |
| `REGION_VERSION_CHECK_ENABLED` | 自动同步开关，设为 false 关闭，默认开启 |

数据库账号需要建表权限，服务初始化时会创建同步、版本历史、授权 Key 和用量统计表。自动同步按北京时间每年 1 月 10 日 02:00 检查上一年数据，失败任务按小时重试，启动时补跑。

## 初始化数据

先创建 `.env.local` 配置对应的数据库，再执行：

```shell
# 生成原始导入文件（输出到 tmp/region-data）
npm run data:build

# 自动建表、导入基础数据，并按版本顺序应用 data/patches/ 下全部 JSON 补丁
npm run data:load -- --input tmp/region-data
```

导入器只接受空表及无版本历史的数据库。基础数据和全部补丁在同一事务中导入，失败会回滚，可修正后重试。旧格式导入文件需重新运行 `npm run data:build` 生成。数据结构见 [建表文件](data/schema/region.sql)，已核验的修正保存在 [data/patches](data/patches/)。

## 部署

```shell
npm run build
npm start
```

默认端口为 3099。后台同步需要持续运行的 Node 服务，部署时使用 HTTPS。也支持 Docker 部署：

```shell
# Docker：数据库地址应能从容器内访问
docker build -t region .
docker run --env-file .env.local -p 3099:3099 region
```

Docker 镜像包含应用和 `data/patches/` 数据包；首次初始化在源码项目中执行。更新数据包后需重新构建镜像。

## 数据维护

日常编辑、同步、冲突处理和版本发布可在后台操作。手动修改立即生效，需在修改日志中归档到草稿并发布；回退只支持有修改日志的版本。存在未归档修改或草稿时，先完成归档发布，再进行自动升级或版本回退。

除首次初始化外，数据包更新、官方同步、编辑和版本管理均在管理后台操作。

用户拉取最新代码后，后台登录、刷新及每 10 秒检查项目中的 `data/patches/*.json`，发现新包会提示“更新全部数据包”。点击后按补丁 `version` 升序执行高于本地当前数据版本的未应用补丁，无需再次抓取民政部数据。代码本身有变化时仍需按正常部署流程重新构建并重启服务。

后台将补丁版本与本地当前国内数据版本比较：本地版本高于或等于补丁版本时跳过，不提示更新，也不会把跳过的补丁记为已执行。提交更新时会在事务锁内再次核对，防止预览后本地版本已升级。实际执行的补丁单独保存版本和 SHA-256 校验值。已发布的补丁文件应保持不变，修正请新增更高版本的 JSON；重复版本或预览后待更新文件变化会阻止更新；本地版本已覆盖的旧包优先跳过，不因旧包内容变化再次提示。旧命令行生成的补丁发布历史会按校验值识别。首次初始化不使用此跳过规则，仍按顺序应用全部补丁。

一次数据包更新在同一事务中执行，全部成功后生成一个可回退版本；失败不会留下部分修改或执行记录。回退后，在版本时间线重新应用该版本，再继续更新数据包。初始化包含的补丁属于基础数据，不提供单独回退。

数据包更新由管理员点击触发；原有民政部自动同步保持独立，不会自动应用本地补丁。

自动同步覆盖中国大陆省、地、县、乡四级；不覆盖港澳台下级和村/社区。失败任务保留断点，勿手工清理同步进度、修改日志和版本历史。

## 开发验证

```shell
npm run typecheck
npm test
```

MySQL 集成测试需指定独立测试实例（root、无密码）；未指定时跳过集成测试。测试会创建并删除专用临时数据库。

```shell
MCA_TEST_SOCKET=/path/to/test-mysql.sock npm test
```
